# PSP Honda Dashboard - Project Context

## What this is

PSP homebrew OBD-II dashboard. Connects to a Vgate iCar 2 ELM327 adapter via WiFi
(192.168.0.10:35000). Reads live engine data and displays it on PSP screen (480x272).
Written in C, compiled with psp-gcc 15.2.0 from /Users/marus/pspdev/bin/.

Output: EBOOT.PBP (drop in PSP/GAME on memory stick).
App icon: assets/icon0.png (144x80 RGB PNG, generated by tools/gen_icon.py).

## Build

```
export PATH="/Users/marus/pspdev/bin:$PATH"
make
```

Pre-existing cosmetic warning: "stubs out of order" from psp-fixup-imports. Does not
affect runtime. Everything else must be zero warnings.

Unit tests (host gcc, no PSP SDK needed): `./test_runner` from project root. 64 tests.

## Key PSP / SDK notes

- **Graphics**: sceGu* / GU_SPRITES, GU_LINES, GU_TRIANGLES. ABGR colour order.
  RGBA macro: `((a<<24)|(b<<16)|(g<<8)|r)`
- **Font**: CP437 8x8 bitmap, bit 0 = leftmost pixel (LSB-first). Fixed mirror bug -
  was `0x80u >> col`, correct is `1u << col`.
- **WiFi**: pspnet_apctl, slots 1-9, `sceNetApctlConnect(slot)`.
- **WLAN switch**: `sceWlanGetSwitchState()` from `<pspwlan.h>` + `-lpspwlan`.
  Setup blocks Continue until switch is ON.
- **SSID names**: `sceUtilityGetNetParam(slot, PSP_NETPARAM_SSID, &d)` from
  `<psputility_netparam.h>` + `-lpsputility`. Reads saved config SSIDs without connecting.
- **Makefile INCDIR**: expanded with addprefix -I inside build.mak. Do NOT put
  `-I$(INCDIR)` in CFLAGS - causes duplicate -I.

## OBD-II PIDs (27 total)

All in `PidIndex` enum in `include/obd/pid.h`, decoded in `src/obd/pid.c`.

| Group        | PIDs |
|-------------|------|
| Core        | RPM, SPEED, COOLANT_TEMP, THROTTLE, IAT, ENGINE_LOAD, VOLTAGE |
| ECU internals | STFT, LTFT, TIMING_ADV, RUNTIME, FUEL_LEVEL, AMBIENT_TEMP |
| Sensors     | MAP, MAF, O2_B1S1, O2_B1S2, BARO, REL_THROTTLE, ACCEL_POS, OIL_TEMP, FUEL_RATE, ETHANOL |
| Diagnostics | MIL_TIME, CLR_TIME, MIL_DIST, CLR_DIST |

### Unsupported PID fallback

- `PidScheduler.fail_count[pid]` counts consecutive NO DATA / '?' responses
- After 3 failures: `skip[pid]=1` (stops polling) + `VehicleState.supported[pid]=2`
- UI uses `draw_fa()` helper: 0=unpolled "...", 1=ok show value, 2=unsupported "N/A" (gray)
- First valid response: `supported[pid]=1`, `fail_count=0`
- SEARCHING.../STOPPED/BUS INIT/UNABLE TO CONNECT are transient bus states - do NOT
  count as failures (ELM327 protocol detection in progress)

### Scheduler priority

- priority 0: polled 2x faster (core PIDs like RPM)
- priority 1: normal
- priority 2: slower
- priority 3: 3x slower (diagnostics, ethanol, baro)

### Selective polling (active_mask)

`PidScheduler.active_mask` is a uint32_t bitmask set each frame in app.c via
`get_mode_pid_mask(g_dash_mode)`. Only bits that are 1 get polled. Skips invisible PIDs
completely, cutting unnecessary OBD round-trips.

`pid_scheduler_next` returns `PID_COUNT` sentinel when nothing is due; `poll_obd` returns
early on that instead of sending a wasted query.

Core mask (RPM | SPEED | FUEL_RATE) is OR'd into every mode's mask so derived trip
data and accel_g always accumulate even on non-core screens.

Per-mode PID counts (excluding core):

| Screen | Extra PIDs polled |
|---|---|
| JDM | COOLANT, VOLTAGE, THROTTLE |
| ANALOG | COOLANT, ENGINE_LOAD, VOLTAGE, OIL_TEMP |
| DIGITAL | COOLANT, THROTTLE, IAT, ENGINE_LOAD, VOLTAGE, OIL_TEMP, FUEL_LEVEL |
| PERF | THROTTLE, ENGINE_LOAD |
| DIAGNOSTICS | MIL_TIME, CLR_TIME, MIL_DIST, CLR_DIST |
| ECONOMY | THROTTLE, ENGINE_LOAD, O2_B1S1, FUEL_LEVEL |
| SENSORS | MAP, MAF, BARO, O2_B1S1, O2_B1S2, OIL_TEMP, ETHANOL, ACCEL_POS, REL_THROTTLE, MIL_* |
| ENGINE | ENGINE_LOAD, STFT, LTFT, TIMING_ADV, IAT, COOLANT, OIL_TEMP, VOLTAGE, MAP, MAF, BARO, FUEL_LEVEL, AMBIENT, RUNTIME |
| TRIP | RUNTIME, FUEL_LEVEL, AMBIENT, IAT, COOLANT, OIL_TEMP, VOLTAGE, ETHANOL |

## Derived metrics (src/telemetry/derived.c)

Computed every frame from VehicleState, no extra PIDs needed beyond what's already polled.

| Field | How computed |
|-------|-------------|
| `gear` | `speed_kmh / rpm` matched against Honda FWD gear ratios (±30% tolerance). 0=neutral, -1=unknown |
| `instant_l100km` | `(fuel_rate_lh / speed_kmh) * 100`. DERIVED_NO_DATA if speed<5 or no FUEL_RATE PID |
| `instant_lh` | raw fuel_rate_lh |
| `trip_l100km` | accumulated over session: `(trip_fuel_l / trip_dist_km) * 100` |
| `trip_fuel_l` | `sum(fuel_rate_lh * dt_h)` each frame |
| `trip_dist_km` | `sum(speed_kmh * dt_h)` each frame |
| `range_km` | `(fuel_level_pct/100 * 45L) / trip_l100km * 100` (45L assumed tank) |
| `accel_g` | `delta(speed m/s) / dt_s / 9.81`, clamped ±2G |
| `power_pct` | `engine_load_pct * (rpm / 8000)`, 0-100% |
| `coasting` | throttle<2% && speed>10 && rpm>800 |
| `idle` | rpm<1100 && speed<3 |
| `afr_state` | from O2 B1S1 voltage: <0.35V=lean(0), 0.35-0.55V=stoich(1), >0.55V=rich(2), -1=unknown |

Trip data resets on Triangle press (TRIP or ECONOMY screen).

Assumed Honda gear ratios (speed_kmh/rpm):
1st=0.0052, 2nd=0.0094, 3rd=0.0142, 4th=0.0195, 5th=0.0267, 6th=0.0337

## Controls

**Main menu** (startup):
- Up/Down: select item
- X: confirm (Connect to OBD / Sample Data / Settings)

**Dashboard**:
- L / R: cycle dashboard screens
- X: cycle colour theme (also jumps to that theme's default screen)
- Start: return to main menu (disconnects OBD/WiFi)
- Select: toggle help overlay (shows all button bindings)
- Triangle (on TRIP or ECONOMY screen): reset trip session
- L+R+Start: emergency disconnect -- works from ANY state including setup and connecting screens

**Status bar hint** (bottom of dashboard): `SEL:HELP  STA:MENU`

|---|---|---|---|---|---|---|
| OEM Honda | Stock clean | line | DIGITAL | off | 1 | off |

### Theme functional fields

- `needle_style` 0=line needle (classic), 1=filled triangle with layered hub (JDM)
- `default_mode` switching themes with X also switches to that theme's home screen
- `redline_flash` semi-transparent red pulse (~4Hz) over entire screen when RPM >= 6500
- `font_scale` 1=normal, 2=large -- scales primary value text in DIGITAL/ANALOG/JDM screens
- `use_animations` 1=lerp needle toward target (smooth), 0=instant jump

Colours are ABGR (PSP GU native). RGBA macro: `((a<<24)|(b<<16)|(g<<8)|r)`.

## Gauges (src/ui/gauge.c)

Two analog gauge renderers:

**`gauge_draw_analog`** -- classic: arc track, fill arc, redline zone outer ring, needle (line or
triangle based on `t->needle_style`), center dot/hub.

**`gauge_draw_analog_jdm`** -- NFS/JDM style: 2px outer rim, redline zone on rim, 3px inner fill
arc, major + minor tick marks with optional numeric labels (`label_scale` param: pass 1000 for
tach to get "0"-"8" labels, 0 for speedo to skip labels), filled triangle needle with shadow,
3-layer center hub. Params: `major_step`, `minor_step`, `label_scale`.

## State machine (app.c)

```
INIT -> MAIN_MENU  (always - user chooses action from menu)

MAIN_MENU --X:Connect--> WIFI_CONNECTING  (if ap_config_idx set)
          --X:Connect--> SETUP            (first time, ap_config_idx==0)
          --X:Demo----> RUNNING           (g_demo_mode=1)
          --X:Settings-> SETUP            (settings mode)

SETUP --done/cancel/O--> MAIN_MENU

WIFI_CONNECTING -> OBD_CONNECTING
OBD_CONNECTING  -> RUNNING
RUNNING         -> OBD_CONNECTING  (if socket drops)

Start (from any non-menu state) -> MAIN_MENU  (disconnects everything)
L+R+Start (from any state)      -> MAIN_MENU  (panic, works inside setup too)
```

`return_to_main_menu()` in app.c: closes socket, shuts WiFi, resets VehicleState /
DtcList / filters / scheduler / derived, clears g_demo_mode / g_in_setup /
g_help_visible / g_obd_status.

## Setup flow

1. Main menu: user chooses "Connect to OBD" -> triggers setup wizard if never configured
2. Welcome screen - blocks Continue until `sceWlanGetSwitchState()==1`
   - O: back to main menu (cancel)
   - X / Start: advance to network picker
3. Network picker - shows actual saved SSID names (sceUtilityGetNetParam)
   - X: test connection (WiFi + OBD probe)
   - O: back to welcome screen
   - Start: confirm slot without testing
4. Settings menu (theme, default mode, poll rate, units, WiFi network)
   - Start: save and exit
   - O: cancel (discard unsaved)

## ELM327 connection sequence

`elm327_probe()` in elm327.c:
1. Tries 8 candidate IP:port combos (Vgate, ESP8266, common clones)
2. Per candidate: connect, flush stale TCP bytes (send CR, drain), send ATI, check response contains "ELM"
3. On success: saves IP:port to settings, returns socket still connected

`elm327_init()` after successful probe:
1. ATZ (full reset, 500ms wait)
2. ATE0 / ATL0 / ATS0 / ATH0 / ATAT1 / ATSP0 (echo off, spaces off, headers off, auto protocol)
3. `elm327_wait_bus_ready()`: polls 0100 until response is NOT SEARCHING.../STOPPED/BUS INIT,
   max 10s. Honda protocol detection takes 5-10s; this prevents premature polling.

## OBD poll logging (debug)

Extensive LOG_D/I output for each frame:
- First valid PID response: `LOG_I("PID[%d] %s first valid: %.2f %s")`
- Transient bus state (SEARCHING etc.): `LOG_D` - not counted as failure
- NO DATA / '?': `LOG_D("fail %d/3")` then `LOG_I` when marked unsupported
- Socket death during poll: `LOG_W`
- Unrecognised response: `LOG_W`
- active_mask change on mode switch: `LOG_I("active_mask 0x%08x -> 0x%08x (mode %d)")`
- OBD connect start: `LOG_I` with endpoint and poll_interval_ms

## Known bugs fixed

- **Stale TCP buffer on re-probe**: After connection drop, re-probe received corrupted ATI
  response (e.g. `'F'` - partial leftover). Fixed: flush stale bytes with `\r` + drain loop
  before ATI in `elm327_probe()`.

- **All PIDs marked unsupported during ATSP0 detection**: ELM327 returns SEARCHING.../STOPPED
  during protocol negotiation (5-10s on Honda). Old code counted these as PID failures,
  hitting fail_count>=3 -> skip=1 for every PID. Fixed: only NO DATA and '?' count.

- **Bus not ready when poll loop starts**: ATSP0 detection takes 5-10s. Old code started
  polling immediately after elm327_init returned, getting SEARCHING on all queries.
  Fixed: `elm327_wait_bus_ready()` waits up to 10s for first valid 0100 response.

- **Double `input_update`**: Two calls per frame zeroed pressed bits -> L/R/X never
  registered in RUNNING state. Fixed: single call inside `handle_input()`.

- **`dtc_read` blocking every frame**: Mode 03 had 2000ms timeout, retried every frame on
  SEARCHING... Fixed: 5-second retry cooldown; diagnostics.c sets read_ok=1 on bus error
  strings.

- **Analog bottom strip overlap with status bar**: Items at y=254 + 8px font = y=262,
  status bar rect starts at y=260. Fixed: items moved to y=249, divider to y=244.

- **Setup welcome screen text overlap**: "2. WLAN switch:" rendered at y=108 (126-18),
  "Make sure:" at y=110. Fixed: WLAN item now at y=142, proper sequential layout.
